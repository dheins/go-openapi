# Petstore example

A complete server generated by goapi from [openapi.yaml](openapi.yaml): an
in-memory pet store with paging, filtering, an API key protecting changes,
RFC 9457 problem details, a server-sent event stream, request logging
middleware and the document served at `/v1/openapi.json`.

```sh
go run ./examples/petstore -key secret
curl localhost:8080/v1/pets
curl -H "X-API-Key: secret" -d '{"name":"Rex","status":"available"}' localhost:8080/v1/pets
```

- [main.go](main.go) wires the generated `api.NewServer` with the options.
- [store.go](store.go) implements the generated `api.Handler`.
- [api/](api) is generated: `go generate ./examples/petstore` rewrites it.
- [main_test.go](main_test.go) exercises it end to end.

## Postman

[petstore.postman_collection.json](petstore.postman_collection.json) has a
request for every operation and error response, each with tests. Import it
into Postman (File, Import), start the server, and run it with the
Collection Runner, leaving out the "Streaming (send manually)" folder: its
event stream stays open until cancelled. Send that request on its own and
create a pet in another tab to see an event arrive.

The collection variables `baseUrl` (default `http://localhost:8080/v1`) and
`apiKey` (default `secret`) can be overridden in a Postman environment.

From the command line, with [Newman](https://github.com/postmanlabs/newman):

```sh
newman run examples/petstore/petstore.postman_collection.json \
  --folder Document --folder Pets --folder Errors
```
