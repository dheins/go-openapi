# Petstore example

A complete server generated by goapi from [openapi.yaml](openapi.yaml): an
in-memory pet store with paging, filtering, an API key protecting changes,
RFC 9457 problem details, a server-sent event stream, a health check, zap
logging with an access log, optional OpenTelemetry traces and metrics, and
the document served at `/v1/openapi.json`.

It is a Go module of its own, so that zap and OpenTelemetry stay out of
goapi's own `go.mod`. Run it from this directory:

```sh
cd examples/petstore
go run . -key secret
curl localhost:8080/v1/pets
curl -H "X-API-Key: secret" -d '{"name":"Rex","status":"available"}' localhost:8080/v1/pets
```

Logging and telemetry flags:

```sh
go run . -key secret -log-encoding console -log-level debug   # readable zap output
go run . -key secret -traces stdout                  # spans as JSON on stdout
go run . -key secret -metrics prometheus             # scrape localhost:9464/metrics
OTEL_TRACES_EXPORTER=otlp OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4318 go run . -key secret
```

Without `-traces`, `-metrics` or `OTEL_*_EXPORTER`, telemetry is off.

- [main.go](main.go) wires the generated `gen.NewServer` with the options,
  and [observability.go](observability.go) builds the logger and the
  telemetry. Its `zapConfig` is the place to change how the example logs:
  level, encoding, time and duration formats, fields on every entry, and
  sampling (off, because sampling per message would drop most access log
  entries, which all share the message "request").
- [store.go](store.go) implements the generated `api.Handler`, with the
  request and response types of `gen/api` and the schema types of
  `gen/model`.
- [gen/](gen) is generated: `go generate` (which runs `go tool goapi`)
  rewrites it.
  It holds `NewServer` (package `gen`), the operations in
  [gen/api](gen/api) (package `api`: the `Handler` interface, request and
  response types, and a handler per operation), and the schema types in
  [gen/model](gen/model) (package `model`).
- [main_test.go](main_test.go) exercises it end to end.

## Postman

[petstore.postman_collection.json](petstore.postman_collection.json) has a
request for every operation and error response, each with tests. Import it
into Postman (File, Import), start the server, and run it with the
Collection Runner, leaving out the "Streaming (send manually)" folder: its
event stream stays open until cancelled. Send that request on its own and
create a pet in another tab to see an event arrive.

The collection variables `baseUrl` (default `http://localhost:8080/v1`) and
`apiKey` (default `secret`) can be overridden in a Postman environment.

From the command line, with [Newman](https://github.com/postmanlabs/newman):

```sh
newman run examples/petstore/petstore.postman_collection.json \
  --folder Document --folder Health --folder Pets --folder Errors
```
